X-Scanner

Diagnóstico local para entender problemas de almacenamiento, procesos y redes.

Docente: ”La solución no solo debe hacer una EXTRACCIÓN, sino debe realizar algún CAMBIO o SALIDA”

01 / PROBLEMÁTICA

El síntoma no explica la causa

  • Una computadora lenta puede tener una aplicación saturando CPU o memoria.
  • El espacio puede consumirse en carpetas personales, papelera o cachés.
  • Una página puede fallar por DNS, ruta, servicio local o red externa.

02 / SOLUCIÓN

De la señal a una decisión

Cliente

Resumen claro, barras, porcentajes, nombres y tamaños.

Técnico

JSON completo, evidencia, limitaciones y reportes TXT.

Acción

Confirmación, autorización del sistema y verificación posterior.

03 / ARQUITECTURA

Web estática + componente local

Brave / React + TypeScript→API HTTP loopback
127.0.0.1:8765→Python + FastAPI
psutil / polkit

Netlify entrega los archivos estáticos. Los datos personales, sesiones, reportes y scripts permanecen en el equipo.

04 / SEGURIDAD

El navegador no ejecuta comandos

  • Origen exacto y sesión temporal en memoria.
  • Operaciones tipadas; nunca shell arbitrario desde la página.
  • Acciones privilegiadas en helper instalado y con lista fija.
  • Scripts del Arsenal se ejecutan como usuario, con límites.

05 / DEMOSTRACIÓN

Medir, cambiar y comprobar

⚠ Problema encontrado: la alerta muestra el valor que realmente midió el laboratorio.

Ejemplos: proceso de prueba con alta CPU, 128 MiB en almacenamiento, servicio HTTP local detenido y archivo eliminado que sigue abierto.

06 / CONEXIÓN

Instalación reproducible

sudo apt install ./xscanner-agent_0.1.0_amd64.deb

xscanner-cli origin https://xscanner.netlify.app

Iniciar X-Scanner desde el menú, copiar el código temporal y vincular. Si el puerto está ocupado, identificar solo la instancia de X-Scanner y volver a lanzarla.

CIERRE

La extracción se convierte en una salida útil

X-Scanner deja evidencia legible, acciones acotadas y un camino de recuperación para la persona y para el técnico.
